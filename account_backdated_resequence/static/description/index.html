Backdated Journal Entry Auto-Resequencing

Post a backdated journal entry and let Odoo put the numbering back in chronological order automatically — no Developer Mode, no manual Resequence step.

Built for Odoo 18.0 — Accounting

The Problem

Journals with a date-based sequence (e.g. MISC/2024/08/0001) always number a new entry with the next available number in its period — regardless of where that entry actually falls chronologically among entries already posted there. Catching up on bookkeeping by entering entries out of date order leaves the numbers silently out of sync with the dates, fixable today only through Settings > Developer Mode > select entries > Actions > Resequence.

How It Works

Nothing to configure. Every journal, every post, automatically.

Post Always Succeeds

The backdated entry posts normally, immediately — nothing is ever blocked while numbering catches up.

Disorder Detected

Right after posting, the module checks whether the entry's own numbering period is now out of chronological order.

Reordered Automatically

If so, that period is reordered using Odoo's own built-in Resequence wizard under the hood — no renumbering logic is reimplemented.

A Dedicated Menu

Open Accounting > Backdated Journal Entries for a purpose-labelled shortcut onto Journal Entries — it behaves no differently, since every fix already applies everywhere by default.

Automatic and Safe by Default

On for every journal, nothing to set up

No journal setting to find or remember — both fixes apply the moment the module is installed. Flat numbering (no year/month in the sequence) is never touched, since there's no date-based order to maintain.

Hash-locked entries are never touched

If any affected entry is already secured by a posting hash, auto-resequencing is skipped entirely for that group — breaking the audit chain is never an option. The entry still posts; a warning is logged pointing to the manual Resequence wizard instead.

Every Renumbering Is Logged

Each automatic renumbering is posted as a chatter message on the affected journal entry — "Automatically resequenced from X to Y due to backdated posting" — the same place all of an entry's other audit history lives. Concurrent backdated posting into the same journal and period is serialized with a row lock before resequencing, so two users posting at once can't produce duplicate or skipped numbers.
